1Introduction

This project builds a machine learning system that reads a short transaction description (e.g. “Uber ride to airport”, “Carrefour groceries”) and predicts its expense category. It supports English and Arabic and is deployed in two demos: a Streamlit web app and an offline Flutter mobile app. The goal is to let a mobile expense app fill in categories automatically.

Categories (10): Food & Dining, Transportation, Shopping & Retail, Entertainment & Recreation, Healthcare & Medical, Utilities & Services, Financial Services, Income, Government & Legal, Charity & Donations.

Preprocessing

English: lowercase, remove punctuation and numbers, stop-word handling. Arabic: diacritics removal and letter normalization. All steps run inside a scikit-learn Pipeline together with TF-IDF, so training and prediction use identical processing. The final vocabularies hold 555 TF-IDF terms (English) and 1,425 terms (Arabic).

3Models

The baseline is TF-IDF + Logistic Regression, compared with Naive Bayes (97.13%), Linear SVM (97.40%) and Random Forest (97.35%). Logistic Regression achieved the best accuracy. The model was tuned with GridSearchCV testing: C (0.1, 1, 10), max_features (1000, 3000, 5000), ngram_range ((1,1), (1,2)). Best params: C=10, max_features=3000, ngram_range=(1,1) for English. A transformer experiment (maaz-zaidi/transaction-classifier-minilm, 22M parameters) is provided as bonus in 03_Transformer_Model.ipynb.

Error analysis

Common confusions: Shopping ↔ Food & Dining (groceries), Entertainment ↔ Food & Dining (restaurants), Transportation ↔ Utilities (car-related). Challenging cases: short descriptions (<5 words), generic terms ("payment", "purchase"), multi-purpose merchants (Amazon, Walmart). Arabic: diacritic variations, colloquial vs MSA, similar merchant names. Solutions: add context features (amount, location, time), increase rare category samples, ensemble methods.

5Deployment & Demos

  • Saved models: final_expense_classifier.joblib and arabic_expense_classifier.joblib, with their TF-IDF vectorizers. A predict(text) function returns the category and confidence.
  • Streamlit demo: paste text or upload a CSV, real-time and batch classification, English and Arabic.
  • Flutter app: 100% offline, pure Dart inference from JSON model files, no server needed. Latency is 20–50 ms.
  • TensorFlow Lite export (bonus): English model 23 KB, Arabic model 58 KB, with 5–15 ms inference (3–5x faster than JSON).

6Conclusions

A TF-IDF + Logistic Regression pipeline classifies transactions with 97.52% accuracy in English and 96.60% in Arabic (realistic imbalanced data), and runs fully offline on mobile with 20-50ms inference time. Models are compact (200 KB combined) and deploy to Flutter with zero dependencies. The Arabic balanced dataset achieved 100% accuracy, demonstrating model capability. Arabic model uses 1,425 TF-IDF features with bigrams (1,2), while English uses 555 features with unigrams (1,1).
Next steps: more categories, fine-tuning on domain-specific data, confidence thresholds, multi-label classification, cloud deployment, and collecting more real-world Arabic transactions.
